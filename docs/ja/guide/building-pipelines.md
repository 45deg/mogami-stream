# パイプラインの組み立て方

タスクの一覧から、未完了のタスクを先頭から2件選び、タイトルの前後の空白を取り除きます。「選ぶ」「変換する」「件数を決める」を、それぞれオペレータに対応させて組み立てます。

## 処理の順番を決める

<<< @/examples/building-pipelines.ts#pipeline

`filter` で未完了のタスクを選び、`map` でタイトルを整え、`take(2)` で結果を2件に制限します。完了済みのタスクは `map` に届かないため、そのタイトルを整える処理は行いません。

`.pipe()` は書いた順に処理をつなぎます。この例の `map` はタスクを文字列に変えるので、その後では `task.done` を参照できません。タスクの状態による絞り込みは、変換前に置きます。

## 値と型を追う

型の `Stream<T>` の `T` は、その段階で流れる値の型です。各段階から出る値を追うと、次のコールバックが何を受け取るか分かります。

| 段階          | 値                           | 型                  |
| ------------- | ---------------------------- | ------------------- |
| `from(tasks)` | タスクのオブジェクト         | `Stream<Task>`      |
| `filter(...)` | 未完了のタスクのオブジェクト | `Stream<Task>`      |
| `map(...)`    | 前後の空白を除いたタイトル   | `Stream<string>`    |
| `take(2)`     | 最大2件のタイトル            | `Stream<string>`    |
| `.toArray()`  | タイトルを集めた配列         | `Promise<string[]>` |

この例の `filter` は対象を選び、`map` は値と型を変えます。`take` は流れる値の型を変えません。`await` した `result` は `string[]` です。

## 制限する件数を決める

`take(2)` が数えるのは、その位置に届いた値です。未完了のタスクを2件選ぶなら、最初の例のように `filter` より後ろに置きます。未完了が2件に満たなければ、得られる結果も2件未満です。

先に入力を2件に制限すると、対象は元の配列の先頭2件だけになります。

<<< @/examples/building-pipelines.ts#input-limit

2件目は完了済みなので、結果は `"Review draft"` の1件です。後にある `"Book room"` は読み取りません。制限したいのが入力件数か、条件に合う件数かで、`take` の位置を選びます。

## 結果の受け取り方を選ぶ

最初の例の `.toArray()` は、結果を配列にまとめて使う場合に向いています。このパイプラインでは `take(2)` があるので、配列に入るのは最大2件です。件数を制限せずに使う場合は、全結果をメモリに保持できるか確認してください。

配列が不要なら、同じ `titles` を `forEach` で1件ずつ処理できます。

<<< @/examples/building-pipelines.ts#consume

この呼び出しは、配列 `tasks` から新たに読み取る別の実行です。前の `result` を使い回すわけではありません。`forEach` は処理結果の配列を作らず、非同期のコールバックも1件ずつ完了を待ちます。

集約や条件による早期終了は[終端処理](./consumers.md)、非同期処理の同時実行は[並行数・容量・需要](./concurrency.md)を参照してください。外部 I/O を扱う場合の停止と解放は[キャンセルと後処理](./lifecycle.md)で説明しています。
